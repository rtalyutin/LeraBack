# Запуск Lera в Timeweb Cloud

Схема остаётся из трёх сервисов: PostgreSQL, LeraBack, LeraFront. Каталог и расписание собираются администратором после входа. Docker-образ бэка сам создаёт схему и первого администратора; тестовые услуги и мастера не добавляются.

## 1. PostgreSQL

Если база уже создана, используй её — не создавай новую для обновления приложения. Для новой установки создай отдельную базу салона и пользователя, владеющего её схемой: приложению нужны права на таблицы, индексы и функции миграции. PostgreSQL 16 подходит к ранее проверенной версии проекта.

Реквизиты возьми из вкладки «Подключение» нужного кластера. Для бэка собери URI `postgresql://USER:PASSWORD@HOST:PORT/DBNAME?sslmode=require`, используя доступный бэку TLS-адрес. Специальные символы пользователя и пароля должны быть закодированы для URI. Сохраняй URI только в переменных бэка. Если используется приватная сеть, база и приложение должны иметь связность в ней; выбранный адрес и TLS нужно проверить при запуске.

Источник: [подключение PostgreSQL](https://timeweb.cloud/docs/dbaas/postgresql/connect-to-database). Настройки реального кластера и резервного копирования ещё требуют проверки.

## 2. LeraBack

В App Platform подключи `rtalyutin/LeraBack`, ветку `main`, способ сборки **Dockerfile**. Dockerfile находится в корне, поэтому поле директории проекта оставь пустым. Контейнер слушает порт **8080**. Путь проверки состояния: **`/livez`**. Для первого управляемого запуска можно отключить автодеплой, чтобы новая публикация кода сама не запускала обновление.

Добавь локальные переменные приложения:

| Переменная | Значение |
| --- | --- |
| `DATABASE_URL` | URI своей базы из шага 1 |
| `SALON_POLICY_JSON` | Строка JSON ниже |
| `SALON_CSRF_SECRET` | Собственное случайное значение не короче 32 байт |
| `SALON_ADMIN_USERNAME` | `salon_admin` или выбранный логин: 3–64 латинских буквы, цифры и символы `_.@-` |
| `SALON_ADMIN_PASSWORD` | Собственный пароль 12–256 символов, только для первого создания администратора |
| `PORT` | `8080` |

`SALON_POLICY_JSON`:

```json
{"timezone":"Europe/Moscow","booking_horizon_days":30,"slot_step_minutes":30,"min_notice_minutes":120,"same_day_allowed":true,"buffer_minutes":0,"room_capacity":1,"allow_parallel_client_bookings":false,"cancel_cutoff_minutes":60,"reschedule_cutoff_minutes":60}
```

Оставь переменные VK незаданными до отдельного подключения сообщества. Это не мешает входу администратора и настройке салона.

После запуска проверь:

1. Лог содержит `Database initialized; administrator ready`, без ошибок миграции или подключения.
2. `https://АДРЕС-БЭКА/livez` возвращает HTTP 200.
3. `https://АДРЕС-БЭКА/healthz` возвращает HTTP 200 и `{"status":"ok"}`. Если здесь 503, процесс работает, но база не готова; проверь реквизиты, доступ и TLS.

Отдельные команды `initialize.py` и `provision_admin.py` для обычного первого запуска не нужны. Второй запуск с другими начальными логином/паролем не заменяет существующего администратора. Если администратор отключён, нужна явная процедура восстановления через разработчика.

Источники: [Dockerfile в App Platform](https://timeweb.cloud/docs/apps/deploying-with-dockerfile), [переменные](https://timeweb.cloud/docs/apps/variables), [проверка состояния](https://timeweb.cloud/docs/apps/healthcheck-path).

## 3. LeraFront

Подключи `rtalyutin/LeraFront`, ветку `main`, способ сборки **Dockerfile**, директория проекта пустая. Порт контейнера **8080**, путь проверки состояния **`/healthz`**.

Единственная переменная: `BACKEND_URL=https://АДРЕС-БЭКА` — HTTPS-адрес без завершающего `/`, без `/api` и других путей. Реквизиты БД, пароль администратора и CSRF-секрет на фронт не передаются.

Запусти приложение и открой его HTTPS-адрес. Войди с начальными логином и паролем. При пустом каталоге откроется конструктор: услуги и длительность → мастера и их услуги → кабинеты и их услуги → часы обоих типов ресурсов, перерывы и выходные.

После успешного входа удали `SALON_ADMIN_PASSWORD` из переменных **бэка** и примени настройки. Повторный запуск использует уже созданного администратора. Логин и действующие сессии должны сохраниться; это отдельная проверка после обновления. Сам `SALON_CSRF_SECRET` сохраняй прежним.

## Проверка результата

Создай тестовую услугу, мастера, кабинет и рабочие часы, затем ручную запись на доступное время. Проверь её длительность, отказ при пересечении, перерыв и отображение в календаре. Изменение часов, затрагивающее запись, должно сначала запросить подтверждение. После повторного запуска данные должны остаться на месте.

При ошибке входа проверь бэк и адрес `BACKEND_URL`. При ошибке базы сохрани журнал; не очищай и не пересоздавай рабочую базу. Если требуется возврат к прежнему коду, используй сохранённую версию приложения с той же базой; откат кода не восстанавливает удалённые данные или отменённые записи.

Деплой Timeweb, настоящая связность/TLS к БД, сборка Docker-образов и доставка VK не подтверждены. Панель Timeweb не открылась в доступном браузере. Пароли и URI базы в чат не отправляй; для дальнейшей проверки достаточно названий сервисов, их публичных адресов и журнала с удалёнными секретами.
